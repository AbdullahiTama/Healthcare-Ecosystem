# Coding Philosophy

Improve existing code before replacing it.

Never duplicate code.

Never create unnecessary abstractions.

Prefer readability.

Prefer composition.

Business logic belongs in services.

Presentation belongs in components.

State should remain predictable.

---

# Quality Standard

Every implementation must include

- Loading state

- Error state

- Empty state

- Responsive layout

- Accessibility

- Logging where appropriate

- Documentation updates

- Test plan

---

# Security

Security is never optional.

Never bypass permissions.

Never expose secrets.

Always explain security implications.
