- (decision) User (Joe) requested a UX review of both apps (CareHub + CareFind) to identify improvements for premium SaaS positioning. Chose Prioritized Improvement Plan as outcome (not spine authoring, not full validate report, not Stitch handoff). Stakes: pre-launch / finding product-market fit. Direction set by user.
- (decision) Audit findings (code, not docs): both apps are inline-style-driven with a real token system (theme.js) that is broadly adopted but drifting. Key gaps: (1) theme.type/space/motion near-dead tokens, hand-typed px everywhere; (2) CareFind declares Geist font but never ships it (only Lora woff2 present) - renders system fonts; (3) foreign palettes (slate #0f172a, amber #fcd34d/#92400e, star-amber #f5b301) mixed into teal/warm-gray; (4) ErrorState defined but used nowhere in either app - catch(e){} swallows read errors; (5) Skeleton/CardSkeleton unused; (6) CareFind PostCard.jsx dead code - Feed.jsx inlines 330-line card; (7) monoliths: Feed 2655, AdminPanel 1887, LiveActivity 1097, POS 883; (8) Register.jsx/Onboarding.jsx are the weakest visual links; (9) duplicated StatTile x2, StatusBadge x2, mobile app bar x2; (10) Landing + BusinessProfile are genuinely premium anchors.
